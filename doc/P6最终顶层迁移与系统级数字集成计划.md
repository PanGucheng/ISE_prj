# 1. 本阶段最终目标

最终数字结构：

```text
                     ┌──────────────────────────────┐
LM393 ×3             │                              │
   ↓                 │                              │
sensor_async[2:0]    │                              │
   ↓                 │                              │
sensor_code_frontend │                              │
   ↓                 │                              │
note_code[2:0] ──────┼────→ DDS → MCP4725 ctrl ───┼→ DAC I2C
                     │                              │
                     │                              │
ADS1115 I2C ─────────┼→ ads1115_ctrl                │
                     │       ↓                      │
                     │   raw CH0/1/2                │
                     │       ↓                      │
                     │ pressure_processor           │
                     │       ↓                      │
                     │ pressure CH0/1/2             │
                     └──────────────────────────────┘
```

注意：

> P6 只负责把现有模块连接成完整系统。

本阶段仍然**不决定压力如何映射到音量或音高**。

所以压力链：

```text
ADS1115 → pressure_processor
```

先正常工作、输出数据即可。

它不能偷偷影响 DDS amplitude、phase 或 note selection。

# 2. 为什么不直接修改 `finger_piano_top.v`

现在仍有两个现实条件没有完成：

```text
1. 3 × LM393 的最终 FPGA LOC 未逐脚确认
2. ADC/DAC 两套 I²C 的 4 个最终 LOC 未逐脚确认
```

因此如果现在直接把正式 top 改成 stage-2：

```text
project top
→ 多出 7 个真实 I/O
→ UCF 尚无确认 LOC
```

就会破坏目前已经验证的 implementation baseline。

所以 P6 分成：

```text
P6A：纯数字系统集成
     不改正式 top / 不改 UCF

P6B：板级顶层迁移
     只有用户确认 7 个接口信号后才能执行
```

P6A 可以立即由 Agent 完成。

P6B 必须等待人工确认。

这样任何 regression 都可以清楚定位到：

> final top cutover

而不是混在其它 RTL 提交里。

# 40. Legacy端口如何处理

stage2 top 不再需要：

```text
key_in[6:0]
key_debug[6:0]
audio_out
```

其中：

```text
audio_out
```

在 DDS/DAC 模式下也不再承担音频输出。

真实音频由：

```text
MCP4725 VOUT
```

进入 LM386。

所以 final stage2 UCF 应移除这些 legacy NET，除非用户明确想保留调试兼容。

---

# 41. 推荐保留 `note_debug`

建议 stage2 至少保留：

```text
note_debug[2:0]
```

原因是上板初期非常有价值：

```text
LM393
→ FPGA
→ stable code
→ decoder
```

是否正确可以直接观察。

如果 IO紧张，也可以后续删除。

---

# 42. 不建议保留 `key_debug[6:0]`

真实硬件已经不是7键。

如果需要 sensor debug，更合理的是：

```text
sensor_debug[2:0]
```

但是否保留由最终 IO预算决定。

本计划不强制。

# 44. I²C上拉仍然是板级器件

UCF只写：

```text

```

不能用 UCF 假装：


真实 ADS/DAC 总线需要：

```text

SCL → 4.7k → 3.3V
```

两条总线分别检查模块自带上拉。

# 51. I²C时序不能仅靠静态时序报告判断

ISE timing 可以验证 FPGA 内部路径。

它不能证明：

```text
4.7k pullup
+
board capacitance
+
real SDA/SCL rise time
```

符合要求。

因此 stage2 implement PASS 之后状态仍只能是：

```text
DIGITAL IMPLEMENTATION PASS
```

不能：

```text
I2C BOARD PASS
```
