# finger_piano ADS1115压力数据处理与标定基础设施开发计划

> **Status**: PLANNED（本计划尚无任何 RTL 落地）
> **Scope**: standalone 压力数据处理 RTL + ISim（无标定、无电压换算、无牛顿压力）
> **Depends on**: P1（ADS1115 driver 与 `adc_chN_raw` / `adc_sample_valid` 接口）
> **Top integration**: NO
> **UCF changes**: NO
> **Hardware programming**: FORBIDDEN
> **Acceptance**: full `verify`（`.\ise.ps1 verify -Project finger_piano`）

## 0. 最高优先级约束

本阶段只处理 ADS1115 已采集完成的三路数字数据，不修改 ADS1115 I²C driver，不参与音符选择，不改变 3-bit LM393 编码，不修改 DDS，不控制 MCP4725，不修改现有 audio_out。真实压力传感器的零点、满量程、轻压/重压阈值目前没有实测依据，因此禁止 Agent 猜测或从网络复制参数。所有校准常量保持默认无校正状态，实际参数必须等用户上板测量后另行填写。

本阶段目标是：

ADS1115 raw data
      ↓
coherent scan frame
      ↓
signed sanitization
      ↓
zero-offset correction
      ↓
three clean pressure channels

而不是：

压力
 ↓
直接改变音高/音量

后者属于后续计划。

## 1. 前置依赖

实施前必须已有：

i2c_master.v

adc_ch2_raw[15:0]

其中：

adc_sample_valid

定义为：

AIN0、AIN1、AIN2 一轮采集全部结束后产生的单周期有效脉冲。

如果当前第一份计划实现的接口名称略有不同，本计划应适配实际实现，但不能复制第二套 ADS1115 驱动。

## 2. 本阶段数据流

建立：

ADS1115
  │
  ├── ch0 raw signed 16 bit
  ├── ch1 raw signed 16 bit
  └── ch2 raw signed 16 bit
          ↓
   pressure_frame_capture
          ↓
   synchronized scan frame
          ↓
   pressure_conditioner
          ↓
┌─────────┼─────────┐
↓         ↓         ↓
P0        P1        P2
15 bit    15 bit    15 bit
corrected corrected corrected

最后输出：

pressure_ch0
pressure_ch1
pressure_ch2
pressure_valid

供以后模块使用。

## 3. 一个重要概念：frame不是“同时采样”

ADS1115只有一个ADC核心，通过内部MUX依次测：

AIN0
AIN1
AIN2

所以：

adc_ch0_raw
adc_ch1_raw
adc_ch2_raw

并不是同一个物理瞬间获得的。

本计划中的：

coherent pressure frame

定义为：

同一轮 CH0→CH1→CH2 扫描结束后形成的一组数据。

不能在文档中写成：

三路同步采样

或：

三个通道同时采样

正确措辞：

三通道轮询扫描帧

人的手指压力变化很慢，因此这种毫秒量级的通道时间差在本项目中可以接受。

## 4. 为什么需要独立数据处理层

不要让以后 DDS 或音量模块直接读取：

adc_ch0_raw

原因是 ADS1115 输出具有硬件层语义：

16-bit two's complement ADC code

而音乐控制层真正应该看到：

non-negative corrected pressure magnitude

中间建立明确边界：

ADC protocol/data format
        ↓
pressure processing
        ↓
musical control

以后即使：

ADC PGA改变；
零点有偏移；
某个传感器静态输出不为0；
ADS1115出现几个负码；

DDS/音量代码都不需要知道。

## 6. pressure_frame_capture.v

推荐接口：

module pressure_frame_capture (
    input  wire        clk,
    input  wire        rst_n_sync,

    input  wire [15:0] adc_ch0_raw,
    input  wire [15:0] adc_ch1_raw,
    input  wire [15:0] adc_ch2_raw,
    input  wire        adc_sample_valid,

    output reg  [15:0] frame_ch0_raw,
    output reg  [15:0] frame_ch1_raw,
    output reg  [15:0] frame_ch2_raw,
    output reg         frame_valid
);

行为：

adc_sample_valid = 0
→ frame保持

adc_sample_valid = 1
→ 同一clk沿锁存三个raw
→ frame_valid拉高1个clk
## 7. Frame必须原子更新

禁止：

先更新CH0
下一拍更新CH1
再下一拍更新CH2

必须：

frame_ch0_raw <= adc_ch0_raw;
frame_ch1_raw <= adc_ch1_raw;
frame_ch2_raw <= adc_ch2_raw;

在同一个：

adc_sample_valid

事件中一起更新。

这样后续逻辑不会看到：

new CH0
old CH1
old CH2

这种半更新状态。

## 8. Reset行为

复位：

frame_ch0_raw = 0
frame_ch1_raw = 0
frame_ch2_raw = 0
frame_valid   = 0

释放复位后，在第一轮 ADS1115 frame 到来之前保持0。

不得生成假的：

frame_valid
## 9. ADS1115的负数如何处理

ADS1115转换寄存器是：

16-bit two's complement

当前应用测：

0V以上单端压力信号

因此正常情况下应主要为正值。

但零输入附近可能出现：

0
+1
-1
-2
...

这是ADC offset/noise可能产生的正常现象。

压力没有“负压力”意义。

因此数据处理层冻结：

$$ raw<0 \Rightarrow pressure=0 $$
## 10. pressure_channel_corrector.v

推荐：

module pressure_channel_corrector #(
    parameter [14:0] ZERO_OFFSET = 15'd0
) (
    input  wire [15:0] raw_code,
    output wire [14:0] corrected_code
);

处理顺序：

ADS1115 signed raw
       ↓
负数？
 ┌─────┴─────┐
 yes         no
 ↓           ↓
 0        raw[14:0]
             ↓
        subtract ZERO_OFFSET
             ↓
          saturate at 0

公式：

$$ P= \max(0,\ max(0,raw)-offset) $$
## 11. 为什么输出15 bit

ADS1115单端正输入正常有效正码范围主要是：

0x0000 ～ 0x7FFF

所以压力幅值只需要：

15 bit unsigned

即：

$$ 0\sim32767 $$

这样后续业务层不需要继续携带：

sign bit

含义。

## 12. Zero Offset

真实 FSR + TL084 + RC + ADS1115 系统即使完全释放，也可能不是严格：

0

例如未来实测可能看到：

CH0 idle = ...
CH1 idle = ...
CH2 idle = ...

但现在没有实测。

因此第一版默认：

ZERO_OFFSET = 15'd0

Agent禁止自己填：

50
100
200

之类猜测值。

## 17. pressure_valid

必须与：

pressure_ch0
pressure_ch1
pressure_ch2

新值一致。

即：

pressure_valid = 1

时，三个输出必须已经代表刚刚完成的这一轮扫描。

Agent不能产生：

下一拍数据才更新

这种接口。

## 18. 是否需要再注册 corrected data

有两种合法实现：

方案A

frame寄存器更新后，corrector是组合逻辑：

frame regs
   ↓
combinational correction

此时：

pressure_valid = frame_valid

即可。

推荐第一版采用这个。

简单，而且没有额外一拍延迟。

## 27. ADS1115错误时怎么处理

这样职责最简单。

以后系统层可以单独监控：

## 34. PGA与校准关系

当前 ADS1115 计划使用：

PGA = ±4.096V

如果以后 PGA 改变：

ADC raw code / Volt

比例也会改变。

所以：

校准参数只对对应 PGA 配置有效。

pressure_calibration.md 必须记录：

ADS1115 PGA setting
VDD
analog gain

避免以后改模拟前端后继续沿用旧校准值。

## 35. 当前模拟链也要记录

RC:
实际R/C

ADS1115 PGA:
001 / ±4.096V

因为任何一个改变：

都会改变。
