状态：本轮局部优化已完成定向验证；面积预算仍未达成。未执行全量 verify，未执行硬件写入。原计划的 500 Slice 是历史功能配置，不能作为当前三通道串口版本的资源结论。

## 1. 为什么资源重新紧张

本轮起点为提交 `5447e81`。构建 `20260922-202944-3b5f28a9` 的全部输入文件 SHA-256 与分析开始时源码一致。MAP 为 702/704 Slice、1175 logic LUT、121 route-through LUT、592 Slice FF、2/3 BRAM。

历史构建的变化如下，均取实际 MAP，不能把跨版本差值当成单模块面积：

| 构建编号 | Slice | logic LUT | Slice FF | 说明 |
|---|---:|---:|---:|---|
| `20260922-105740-6421d710` | 500 | 806 | 384 | 早期优化版本，没有当前实时三通道串口输出 |
| `20260922-140658-227522d2` | 607 | 955 | 471 | 约束、配置、顶层、系统连接和 UART 均有变动 |
| `20260922-160404-d57f6287` | 662 | 1042 | 502 | 相对上一行，输入源文件仅 OLED 顶层变化 |
| `20260922-164936-38e35b54` | 662 | 1042 | 502 | ADC 错误码细分与速率配置变动 |
| `20260922-202944-3b5f28a9` | 702 | 1175 | 592 | ADC 修复和实时三通道上报版本 |

500 Slice 版本的 XST 日志明确显示 `GEN_ADC.ch0_q/ch1_q/ch2_q` 等未消费输出被裁剪。现在 UART 真正读取这些数据，因此一部分增量是恢复真实数据通路的成本。当前 ADC 等待计数器仍为 16 位（12 MHz 下阈值 24000），不能把全部增长解释为计数器重新扩大到了 32 位。

另一个因素是 MAP 打包：原命令未指定 `-c`，工具默认值为 100。逻辑减少时 occupied Slices 不一定同步下降。必须分别比较 logic LUT、route-through LUT、FF、Slice 与 BRAM。

## 2. 已实施的改动

### 2.1 DDS 同步 ROM 与预取

- 新增 `src/audio/sine_rom_12bit_sync.v`：256×12 全周期同步 ROM，由 XST 推断为一块 BRAM。
- `tools/gen-dds-sine-rom.py` 直接展开原 `sine_lut_12bit.v` 的整数表和象限运算，绝不重新用浮点正弦生成近似值。`--check` 可检查生成物是否过期。
- 原组合 LUT 保留，供独立测试和冻结参考实现使用；参考实现只加入仿真 sources。
- `SAMPLE_DIV >= 2` 保证正常采样之间至少有一个时钟供 ROM 预取推进后的相位。切音当拍向 ROM 提交地址零，下一拍采样也能拿到中点。
- 外部 `dac_code`、`dac_code_valid` 的节奏、复位和切音语义保持不变。

| 边界 | 预取与外部结果 |
|---|---|
| 复位释放后首次采样 | 采样计数器尚未到期时已读取相位零；复位输出仍为 2048 |
| 正常采样 | 输出已预取的当前相位值，然后推进相位 |
| 切音与采样同拍 | 原切音分支强制中点，valid 节拍不移位 |
| 切音在采样前一拍 | 切音边沿读取零；下一拍输出零相位中点 |
| 切音在采样后一拍 | 当拍输出中点并重启相位，不重启分频器 |
| 静音、下游 busy | 保留固定采样时间轴，静音中点不变 |

同步 ROM 推断依据为 XST 对同步输出 ROM 的支持，参见 [Xilinx UG627](https://docs.amd.com/api/khub/documents/TRSkTbERlQzP8~B_44CW7A/content)。是否实际进入 BRAM 仍以本轮 XST `INFO:Xst:3044/3225` 和 MAP 的 3/3 BRAM 为准。

### 2.2 UART 结构精简

- 普通消息字符位置与 ADC 分段字符位置共用一个 4 位计数器；消息长度也明确为 4 位。
- 每个通道仍在原来的时刻锁存 16 位快照，改为四选一读取半字节，避免每个字符都移位整个 16 位寄存器。
- 保留 READY、OLED OK/NACK、ADC ERR、NOTE、三通道 ADC OK 的文本、优先级、发送握手和现有上报频率。
- 未改 ADC 控制器、I²C master、速率、管脚及约束。

### 2.3 可复现的 MAP 配置

工程配置采用 `optimization=Area`、`optimizationLevel=1`、`mapPackFactor=80`。

工具新增可选配置字段，映射为 `map -c 80`；正式命令集合和 programmer 完全不变。未配置的其他工程保持原命令。值必须是 JSON 整数 0～100，仅支持已核对的 Spartan-3 家族；拒绝字符串、越界值、其他器件家族和命令注入文本。工具隔离自测已 PASS。

这是打包目标，不是保证只占 80%，也不是逻辑资源变少的证据。配置越小不保证结果越好。

1. 阅读本文、当前 project.json 和仓库 AGENTS；先检查本地是否仍与本轮源码一致。不要拿旧 bit 当成新实现。
2. 按下方最终交付记录确认 bit 路径和 SHA-256。需要自行重建时先 `check -Stage bitstream`，再 `build -Stage bitstream`；重新阅读该次 MAP/PAR/TWR，不能拿本文的时序结论套到另一构建。
3. 硬件写入授权单独取得。本轮没有烧录授权，不沿用历史一次性 JTAG 许可。获得授权后只用正式 `program -Mode Jtag -ConfirmHardwareWrite`；不写 ISF。
4. 使用 `tools/capture-adc-uart.ps1 -ListPorts` 确认实际串口，随后用 `-Port <实际端口> -BitFile <本次bit> -Seconds 60 -BaudRate 115200 -Label resource_o3` 保存原始数据和摘要。依次按压三只传感器，确认三个通道分别响应且没有 ADC ERR。UART 提供的 bit 身份仍是操作员声明。
5. 确认 OLED 显示、音符切换和静音；实际测量 DAC 输出的七音频率及幅值。仿真 PASS 不替代这些板级结论。
6. 根据需要安排完整 verify；本轮有意没有执行，不能写成“全量验收通过”。任何失败保留日志并区分原有缺口与本次回归。

## 6. 下一轮优化优先级

1. **UART 固定文本存储与共享发送控制。** 现在仍有多组组合字符 case。先量化，将固定文本放进现有 ROM 的空闲地址/可用读端口是候选；须核实器件原语与端口布局，新增端口模型与并发访问测试。当前已经 3/3 BRAM，不能再单独占第四块。保留当前文本协议，不默认删诊断。
2. **OLED 局部状态机和位发送选择。** 逐项比较二进制/原状态编码和数据路径，不能只按 FF 数量估算收益。每次记录同口径 MAP，并回归 ACK/NACK、启动延迟和显示更新。
3. **接入真实压力音量前重新预算。** 保持源数据有实际消费者；将完整压力链与增益功能一起实现，量化新增资源。不得通过断开 ADC 数据、减少通道或裁剪错误恢复得到虚假的空闲面积。

继续使用 ≤560 Slice（音量前）和争取 ≤600 Slice（真实压力音量后）作为预算目标，当前均不作已达成声明。停止盲目收窄 ADC 超时或以更改 ADC 时序来换资源。
