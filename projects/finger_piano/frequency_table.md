# 七音频率表与半周期计数值

## 1. 计算公式

`tone_generator.v` 在 `clk` 上升沿对半周期计数，达到 terminal count 时翻转 `audio_out`。半周期计数值：

```
N = round( SYS_CLK_HZ × 10 / (2 × f_dHz) )        （Verilog 整数就近取整，见下）
f_out = SYS_CLK_HZ / (2 × N)                       （理论输出频率）
误差 = (f_out − f_nom) / f_nom × 100%
```

其中 `f_dHz` 是音符标称频率的 **0.1 Hz 整数表示**（例如 261.62 Hz → 2616），RTL 中写成：

```verilog
localparam integer HP_C4 = (SYS_CLK_HZ * 10 + 2616) / (2 * 2616);
```

即 `+ f_dHz` 实现就近取整（分母 `2 × f_dHz` 的一半就是 `f_dHz`）。

### 为什么用 0.1 Hz 整数而不是实数

XST 对 Verilog `real` 常量在可综合表达式中的支持受限且容易告警，因此频率表全部用整数（0.1 Hz 单位）表示。0.1 Hz 量化带来的额外标称误差最大约 0.05 Hz（对 261.6 Hz 约 0.019%），与取整误差同量级，已计入下表。

## 2. SYS_CLK_HZ = 50 000 000 时的表

> 该值是**占位默认值**，实际晶振频率确定后必须修改 `src/finger_piano_cfg.vh` 的 `` `SYS_CLK_HZ `` 并按第 4 节重算本表。

| 音符 | 唱名 | 标称频率 f_nom (Hz) | f_dHz (0.1 Hz) | 半周期计数 N | 理论输出 f_out (Hz) | 频率误差 |
|---|---|---|---|---|---|---|
| 1 | C4 | 261.62 | 2616 | 95566 | 261.5993 | −0.0079% |
| 2 | D4 | 293.67 | 2937 | 85121 | 293.6996 | +0.0101% |
| 3 | E4 | 329.63 | 3296 | 75850 | 329.5979 | −0.0097% |
| 4 | F4 | 349.23 | 3492 | 71592 | 349.2010 | −0.0083% |
| 5 | G4 | 391.99 | 3920 | 63776 | 391.9970 | −0.0018% |
| 6 | A4 | 440.00 | 4400 | 56818 | 440.0014 | +0.0003% |
| 7 | B4 | 493.88 | 4939 | 50618 | 493.8955 | −0.0031% |
| — | 无音符 | — | — | — | `audio_out = 0` | 静音 |

**结论**：全部七个音符的理论误差绝对值 ≤ 0.011%，满足“误差 < 1%”的课程要求。该表反映的是数字取整误差；实际听到的频率还会叠加晶振自身精度（常见有源晶振 ±20~50 ppm，远小于 1%）。

上表的输出频率由 `f_out = SYS_CLK_HZ / (2N)` 计算，例如 C4：`50 000 000 / (2 × 95566) = 261.5993 Hz`。

## 3. 与 RTL 的一致性

- 表中 `N` 由 `tone_generator.v` 内联的 `localparam` 常量表达式独立算出，两者必须一致；若修改公式需同时更新本文件。
- `tb_tone_generator.v` 不查表断言，而是**实测**相邻两个 `audio_out` 翻转沿之间的 `clk` 周期数 `N_meas`，用实数算出 `f = TB_SYS_CLK_HZ / (2 × N_meas)` 并与实数标称表比较，要求 `|误差| < 1%`。这样表与 RTL 都错也不能同时骗过测试。
- `tb_finger_piano_top.v` 对顶层做同样的实测抽查。

## 4. 改了 SYS_CLK_HZ 之后如何重算本表

1. 修改 `src/finger_piano_cfg.vh` 的 `` `SYS_CLK_HZ ``；
2. 在仓库根运行下面这段 PowerShell（整数运算与 RTL 完全等价），把输出贴回第 2 节的表格：

```powershell
$sysClkHz = 50000000   # 改成实际晶振频率
$notes = @(
  @{ Name = '1 C4'; Hz = 261.62 }, @{ Name = '2 D4'; Hz = 293.67 },
  @{ Name = '3 E4'; Hz = 329.63 }, @{ Name = '4 F4'; Hz = 349.23 },
  @{ Name = '5 G4'; Hz = 391.99 }, @{ Name = '6 A4'; Hz = 440.00 },
  @{ Name = '7 B4'; Hz = 493.88 }
)
$notes | ForEach-Object {
  $dHz  = [int][math]::Round($_.Hz * 10)
  $n    = [int](($sysClkHz * 10 + $dHz) / (2 * $dHz))   # 与 RTL 一致：整数除法（截断）
  $fout = $sysClkHz / (2.0 * $n)
  [pscustomobject]@{
    音符 = $_.Name; dHz = $dHz; N = $n
    理论输出Hz = [math]::Round($fout, 4)
    误差pct    = [math]::Round((($fout - $_.Hz) / $_.Hz) * 100, 4)
  }
} | Format-Table -AutoSize
```

3. 同时更新 UCF 中 `TIMESPEC PERIOD` 的注释值（`1000 / SYS_CLK_MHz` 纳秒）。

## 5. 数值边界

- **配置上限约 214 MHz 来自 Verilog/XST 的 32 位有符号整数常量表达式 `SYS_CLK_HZ * 10` 的溢出边界**（`2^31 − 1 ≈ 2.147e9`），**不是** `FP_TONE_CNT_WIDTH = 24` 的计数器容量限制。50 MHz 默认配置完全处于安全范围；本项目实际使用的 XC3S50AN 最小系统板不会接近该上限。这是代码常量表达式的边界，不是器件时钟性能声明。
- **半周期计数器位宽** `FP_TONE_CNT_WIDTH = 24` 支持最大计数值 `2^24 − 1 = 16 777 215`：50 MHz 下最高音符 B4 只需 50618（16 位），即使 200 MHz 也只需约 202 000（18 位），因此 24 位有充足裕量。若系统时钟异常高导致 `N ≥ 2^24`，计数值会被截断——请同步增大该宏。
- **最小系统时钟**：当 `SYS_CLK_HZ < 2 × f_nom` 时半周期计数会算成 0 或 1，RTL 已把 `half_target` 钳位到最小 1（此时输出为 `clk/2`，已无法表达目标音高，仅作为不产生非法状态的保护）。正常使用要求 `SYS_CLK_HZ` 远大于 2 × 493.88 Hz。
- **滤波计数器位宽** `FP_FILTER_CNT_WIDTH = 24`：默认 50 MHz、10 ms 需要计数 500 000 个周期，19 位已足够；项目采用 24 位为更高系统时钟和更长滤波时间预留裕量。约束条件为 `SYS_CLK_HZ × KEY_STABLE_MS < 2^24`（50 MHz 下约 335 ms 上限）。
