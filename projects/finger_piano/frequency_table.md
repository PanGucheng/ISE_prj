# 七音频率表与半周期计数值

## 1. 计算公式

`tone_generator.v` 在 `clk` 上升沿对半周期计数，达到 terminal count 时翻转 `audio_out`。半周期计数值：

```
N = round( SYS_CLK_HZ × 10 / (2 × f_dHz) )        （Verilog 整数就近取整，见下）
f_out = SYS_CLK_HZ / (2 × N)                       （理论输出频率）
误差 = (f_out − f_nom) / f_nom × 100%
```

其中 `f_dHz` 是音符标称频率的 **0.1 Hz 整数表示**（例如 261.62 Hz → 2616），RTL 中写成：

```verilog
localparam integer HP_C4 = (SYS_CLK_HZ * 10 + 2616) / (2 * 2616);
```

即 `+ f_dHz` 实现就近取整：`f_dHz` 正好是分母 `2 × f_dHz` 的一半，所以这一步是「**先加半个除数**」。

**关键细节**：加了半个除数之后，**必须做向零截断的整数除法**。Verilog 中两个正整数相除的结果就是截断（等价于 `floor`）；如果用带舍入的除法，结果会与 RTL 不符。实测：PowerShell 的 `[int]` 强制转换采用「就近舍入（round-half-to-even）」，用 `[int]((SYS_CLK_HZ*10 + f_dHz) / (2*f_dHz))` 会把 F4 算成 71593、A4 算成 56819，而 RTL 给的是 71592 和 56818。本文件第 4 节的脚本因此**显式使用 `[math]::Floor`**，以保证与 RTL 的截断语义严格等价。

### 为什么用 0.1 Hz 整数而不是实数

XST 对 Verilog `real` 常量在可综合表达式中的支持受限且容易告警，因此频率表全部用整数（0.1 Hz 单位）表示。0.1 Hz 量化带来的额外标称误差最大约 0.05 Hz（对 261.6 Hz 约 0.019%），与取整误差同量级，已计入下表。

## 2. SYS_CLK_HZ = 2 000 000 时的表

> 本工程实际使用的外部有源晶振为 **2 MHz**（已确认），对应 UCF 时钟约束 `PERIOD = 500 ns`。更换晶振时请修改 `src/finger_piano_cfg.vh` 的 `` `SYS_CLK_HZ `` 并按第 4 节重算本表。

| 音符 | 唱名 | 标称频率 f_nom (Hz) | f_dHz (0.1 Hz) | 半周期计数 N | 理论输出 f_out (Hz) | 频率误差 |
|---|---|---|---|---|---|---|
| 1 | C4 | 261.62 | 2616 | 3823 | 261.5747 | −0.0173% |
| 2 | D4 | 293.67 | 2937 | 3405 | 293.6858 | +0.0054% |
| 3 | E4 | 329.63 | 3296 | 3034 | 329.5979 | −0.0097% |
| 4 | F4 | 349.23 | 3492 | 2864 | 349.1620 | −0.0195% |
| 5 | G4 | 391.99 | 3920 | 2551 | 392.0031 | +0.0034% |
| 6 | A4 | 440.00 | 4400 | 2273 | 439.9472 | −0.0120% |
| 7 | B4 | 493.88 | 4939 | 2025 | 493.8272 | −0.0107% |
| — | 无音符 | — | — | — | `audio_out = 0` | 静音 |

**结论**：全部七个音符的理论误差绝对值 ≤ **0.020%**，满足“误差 < 1%”的课程要求。该表反映的是数字取整误差；实际听到的频率还会叠加晶振自身精度（常见有源晶振 ±20~50 ppm，远小于 1%）。

上表的输出频率由 `f_out = SYS_CLK_HZ / (2N)` 计算，例如 C4：`2 000 000 / (2 × 3823) = 261.5747 Hz`。

> **关于 C4 与 F4 的“1 个计数差”**：若改用实数频率直接取整 `round(SYS_CLK_HZ / (2 × f_nom))`，C4 会得到 **3822**、F4 会得到 **2863**。本工程 RTL 使用的是 0.1 Hz 整数频率表（261.6 Hz / 349.2 Hz）加「先加半个除数再截断」，因此得到 **3823 / 2864**。两种取值对应的误差分别是 C4 −0.017% / +0.009%、F4 −0.020% / +0.007%，都远小于 1%。**表格以 RTL 实际算法为准**（第 3 节要求两者一致）。若要让逐位结果与实数取整完全相同，需要把 `tone_generator.v` 的频率常量从 0.1 Hz 精度改为 0.01 Hz——那属于 RTL 修改，须另行评审，本轮未做。

## 3. 与 RTL 的一致性

- 表中 `N` 由 `tone_generator.v` 内联的 `localparam` 常量表达式独立算出，两者必须一致；若修改公式需同时更新本文件。
- `tb_tone_generator.v` 不查表断言，而是**实测**相邻两个 `audio_out` 翻转沿之间的 `clk` 周期数 `N_meas`，用实数算出 `f = TB_SYS_CLK_HZ / (2 × N_meas)` 并与实数标称表比较，要求 `|误差| < 1%`。这样表与 RTL 都错也不能同时骗过测试。
- `tb_finger_piano_top.v` 对顶层做同样的实测抽查。

## 4. 改了 SYS_CLK_HZ 之后如何重算本表

1. 修改 `src/finger_piano_cfg.vh` 的 `` `SYS_CLK_HZ ``；
2. 在仓库根运行下面这段 PowerShell，把输出贴回第 2 节的表格。脚本用 `[int64]` 计算分子分母、用 `[math]::Floor` 显式向下取整，与 RTL 的正整数截断除法严格等价（不要改回 `[int](浮点除法)`，那会引入舍入差异）：

```powershell
$sysClkHz = 50000000   # 改成实际晶振频率
$notes = @(
  @{ Name = '1 C4'; Hz = 261.62 }, @{ Name = '2 D4'; Hz = 293.67 },
  @{ Name = '3 E4'; Hz = 329.63 }, @{ Name = '4 F4'; Hz = 349.23 },
  @{ Name = '5 G4'; Hz = 391.99 }, @{ Name = '6 A4'; Hz = 440.00 },
  @{ Name = '7 B4'; Hz = 493.88 }
)
$notes | ForEach-Object {
  $dHz  = [int][math]::Round($_.Hz * 10)     # 0.1 Hz 整数，与 RTL 的频率表一致
  $num  = [int64]$sysClkHz * 10 + $dHz       # 先加半个除数（f_dHz 就是半个除数）
  $den  = [int64]2 * $dHz
  # 与 Verilog 正整数除法等价：显式向零截断（此处各数均为正，floor == truncate）
  $halfPeriod = [int][math]::Floor($num / [double]$den)
  $fout = $sysClkHz / (2.0 * $halfPeriod)
  [pscustomobject]@{
    音符       = $_.Name
    dHz        = $dHz
    N          = $halfPeriod
    理论输出Hz = [math]::Round($fout, 4)
    误差pct    = [math]::Round((($fout - $_.Hz) / $_.Hz) * 100, 4)
  }
} | Format-Table -AutoSize
```

**自检**：在 2 MHz 下运行后，`N` 一列必须依次为 `3823 3405 3034 2864 2551 2273 2025`，与 `tone_generator.v` 内联的 `localparam` 完全一致（50 MHz 时的旧值为 `95566 85121 75850 71592 63776 56818 50618`）。若不一致，说明脚本的取整方式与 RTL 不同，应先修脚本，不要改表格去迁就脚本。

3. 同时更新 UCF 中 `TIMESPEC PERIOD` 的注释值（`1000 / SYS_CLK_MHz` 纳秒）。

## 5. 数值边界

- **配置上限约 214 MHz 来自 Verilog/XST 的 32 位有符号整数常量表达式 `SYS_CLK_HZ * 10` 的溢出边界**（`2^31 − 1 ≈ 2.147e9`），**不是** `FP_TONE_CNT_WIDTH = 24` 的计数器容量限制。本工程的 2 MHz 配置距离该边界极远（`2e7`）。这是代码常量表达式的边界，不是器件时钟性能声明。
- **半周期计数器位宽** `FP_TONE_CNT_WIDTH = 24` 支持最大计数值 `2^24 − 1 = 16 777 215`：2 MHz 下最高音符 B4 只需 2025（11 位），因此 24 位裕量极大。若系统时钟提高导致 `N ≥ 2^24`，计数值会被截断——请同步增大该宏。
- **最小系统时钟**：当 `SYS_CLK_HZ < 2 × f_nom` 时半周期计数会算成 0 或 1，RTL 已把 `half_target` 钳位到最小 1（此时输出为 `clk/2`，已无法表达目标音高，仅作为不产生非法状态的保护）。正常使用要求 `SYS_CLK_HZ` 远大于 2 × 493.88 Hz，本工程 2 MHz 满足且裕量大。
- **滤波计数器位宽** `FP_FILTER_CNT_WIDTH = 24`：RTL 中的稳定周期数是 `STABLE_CYCLES = (SYS_CLK_HZ / 1000) * STABLE_MS`（**先把 Hz 取整到 kHz，再乘 ms**）。本工程 2 MHz、10 ms → `(2000000/1000)*10 = 20000` 个周期，15 位就够（`2^15 = 32768`），24 位裕量很大。容量条件为

  ```
  (SYS_CLK_HZ / 1000) * KEY_STABLE_MS  <=  2^FP_FILTER_CNT_WIDTH
  ```

  注意**不能漏掉 `/1000`**：`ms` 与 `Hz` 之间差一个千倍因子，写成 `SYS_CLK_HZ * KEY_STABLE_MS` 会把容量要求放大 1000 倍。2 MHz、24 位下 `KEY_STABLE_MS` 的上限约 **8388 ms**（`2^24 / (2000000/1000) = 16777216 / 2000 = 8388.6 ms`）；24 位计数器无需缩位。RTL 比较的是 `cnt >= STABLE_CYCLES - 1`，因此 `STABLE_CYCLES <= 2^W` 即为恰好充分条件。
